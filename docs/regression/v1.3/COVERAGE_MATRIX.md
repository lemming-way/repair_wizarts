# Regression Pack — Article Format 1.3

## 1. Назначение и границы

Набор проверяет только функциональность формата статей v1.3 и непосредственно связанный с ней код:

- ZIP-приём и импорт демонстрационных статей;
- разбор и валидацию `article.json`, блоков и реестра `assets`;
- сохранение/возврат JSON статьи в рамках article API;
- отображение всех 12 типов блоков единым `ArticleRenderer`;
- одинаковое отображение в Preview и опубликованной статье;
- корректность медиа-ссылок, изоляцию ошибок блоков и безопасный вывод содержимого.

Вне области проверки: авторизация как общая подсистема, пользователи, заказы, платежи, чаты, комментарии как самостоятельный функционал, поиск/каталог вне получения статьи, прочие модули приложения, общий coverage всего приложения и производительность приложения в целом.

Проверки ZIP Slip, decompression bomb, лимитов распаковки, MIME-sniffing и других дополнительных ZIP security controls отнесены к следующему этапу и в критерии приёмки этого набора не входят. Совместимость с ZIP Data Descriptor — отдельная функциональная проверка совместимости, не security-тест.

## 2. Демонстрационные статьи

| Статья | Домен | Блоков | Медиа | Особенности |
|---|---|---:|---:|---|
| smartphone | смартфоны | 11 | 3 | GLB и полный набор technical_knowledge |
| electric_kettle | бытовая техника | 11 | 2 | галерея и диагностика сетевого прибора |
| toilet_cistern | сантехника | 10 | 2 | галерея и пошаговая замена механизма |

Архивы: `smartphone.zip`, `electric_kettle.zip`, `toilet_cistern.zip`. Распакованные исходники и контрольные суммы перечислены в `MANIFEST.json`.

Все 12 типов представлены в совокупности трёх статей; не требуется искусственно помещать каждый тип в каждую статью. SVG — схематические авторские иллюстрации, GLB — упрощённая демонстрационная геометрия. Материалы не предназначены для публикации как проверенные инструкции для конкретных моделей.

## 3. Матрица типов блоков

Проверяется не только наличие блока, но и его поля, семантика, порядок, необязательные атрибуты и деградация при повреждённых данных.

| ID | Тип | Позитивные проверки рендерера | Негативные/граничные проверки |
|---|---|---|---|
| BLK-01 | `heading` | Уровни 2, 3, 4; текст; порядок относительно соседних блоков | level ниже/выше диапазона; отсутствующий текст; неизвестный тип не должен ломать следующие блоки |
| BLK-02 | `paragraph` | Обычный текст, переносы и спецсимволы | HTML-подобная строка остаётся текстом; отсутствующий/нестроковый text не должен создавать исполняемую разметку |
| BLK-03 | `image` | file, alt, caption; mediaBaseUrl; открытие увеличенного изображения | отсутствующий/небезопасный URL; отсутствующий файл; ошибка изображения не ломает статью |
| BLK-04 | `gallery` | 2+ изображения, подписи, alt, горизонтальная прокрутка, навигация и lightbox | пустой images; один элемент; некорректный элемент; недоступное изображение исключается без сбоя остальных |
| BLK-05 | `video` | Поддерживаемый YouTube URL и caption; безопасный embed URL | неподдерживаемая платформа, повреждённый ID, javascript: URL; iframe не создаётся для недопустимой ссылки |
| BLK-06 | `list` | ordered → ol; unordered → ul; порядок и текст элементов | пустой/отсутствующий items; неизвестный style; элементы не интерпретируются как HTML |
| BLK-07 | `quote` | text и необязательный caption | отсутствие caption; HTML-подобный текст; пустая цитата |
| BLK-08 | `callout` | info, warning, danger, tip; title и text | неизвестный style; отсутствующий title; отсутствующий text; блок не меняет порядок соседей |
| BLK-09 | `steps` | Порядок и нумерация; title/text; optional image/warning | пустой items; шаг без optional-полей; недоступное изображение; предупреждение привязано к своему шагу |
| BLK-10 | `table` | headers, rows, пустые ячейки, текстовые значения | пустые headers/rows; строка неправильной длины должна быть отклонена валидатором; HTML не исполняется |
| BLK-11 | `code` | language, многострочный text, сохранение пробелов и переносов, копирование | неизвестный language отображается как текстовая метка; команды не исполняются; HTML/JS остаётся текстом |
| BLK-12 | `model_3d` | GLB, alt/caption, controls, camera, scale; отложенная загрузка | неверный/недоступный файл; ошибка загрузки не блокирует остальные блоки; небезопасная ссылка не загружается |

## 4. ZIP-импорт и структура архива

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| ZIP-01 | Корректный архив: `article.json` в корне и `media/` | Импорт успешен |
| ZIP-02 | Архив без `article.json` | Отказ с диагностикой, ничего не сохраняется |
| ZIP-03 | Нет каталога/файлов `media/` | Отказ согласно контракту формата |
| ZIP-04 | Повреждённый ZIP / усечённый local header / усечённые данные | Контролируемый отказ без частичного результата |
| ZIP-05 | Методы ZIP Store и Deflate | Оба поддерживаемых метода читаются |
| ZIP-06 | Повторяющиеся имена файлов внутри архива | Отказ либо однозначная диагностируемая обработка; не допускать молчаливой подмены |
| ZIP-07 | Архив содержит вложенный путь `media/subdir/file` | Файл корректно импортируется и ссылка разрешается |
| ZIP-08 | Корректный архив с дополнительными неиспользуемыми файлами в media | Неиспользуемые файлы не ломают импорт; политика хранения фиксируется реализацией |
| ZIP-09 | ZIP с Data Descriptor (general purpose bit 3) | Функциональная совместимость: архив должен импортироваться после поддержки формата; текущий `build-articles.mjs` явно отклоняет такой архив — отмечать как известное ограничение, не засчитывать как пройденный тест |
| ZIP-10 | Повторный импорт тех же трёх архивов | Результат детерминирован по содержимому; каталог и файлы не дублируются |

Для ZIP-01…ZIP-10 проверяется также, что ошибка одного архива не приводит к выдаче частично собранной статьи. Проверка ZIP Slip и дополнительных защитных лимитов выполняется отдельно на следующем этапе.

## 6. Сохранение, API и Preview

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| DATA-01 | Импорт статьи без technical_knowledge | JSON принят и сохранён |
| DATA-02 | Импорт статьи с technical_knowledge | Полный объект сохранён |
| DATA-03 | Round-trip JSON → storage → API response | Нет потери полей, массивов, вложенности и значений |
| DATA-04 | Неизвестные дополнительные поля | Сохранены без пересборки JSON только из известных полей |
| DATA-05 | API отдаёт полный набор blocks и корректный media_base_url | Все локальные файлы разрешаются |
| DATA-06 | Preview использует тот же ArticleRenderer, что опубликованная статья | Одинаковая структура и визуальная семантика |
| DATA-07 | technical_knowledge присутствует | Не отображается как текст или отдельный блок статьи |
| DATA-08 | Ошибка одного медиа/блока | Остальные корректные блоки продолжают отображаться |

Если серверная реализация/API не доступна в текущем репозитории или тестовом окружении, DATA-01…DATA-05 выполняются как отдельные интеграционные проверки на тестовом backend; они не заменяются проверками локального каталога.

## 8. Безопасный вывод содержимого

Это функциональные проверки рендерера, а не полный аудит безопасности ZIP:

- HTML-подобные строки в text/title/caption/code выводятся как текст, не создают DOM-элементы;
- `javascript:` не используется как URL изображения, видео или модели;
- iframe создаётся только для URL поддерживаемой платформы;
- команды в блоке code не исполняются;
- неизвестные типы и технические данные не становятся исполняемым/видимым содержимым статьи.

## 9. Автоматизация и критерии завершения

Автоматизируются unit/component-тестами:
- рендер каждого из 12 типов;
- порядок блоков и ключевые поля;
- неизвестные типы, технические данные и ошибочные значения;
- безопасный вывод строк и проверка URL;
- утилиты разрешения media URL;
- импортёр ZIP — отдельными интеграционными тестами на временных архивах.

Ручные/integration проверки:
- Preview против опубликованной статьи;
- реальный backend storage/API round-trip;
- мобильные ширины и интерактивность галереи/таблиц/кода;
- GLB в реальном браузере.

Набор считается пройденным, когда все обязательные тесты имеют результат PASS, а известные ограничения (в частности ZIP Data Descriptor, если поддержка ещё не добавлена) явно перечислены. Общий coverage приложения, общий build и тесты посторонних модулей не входят в критерии приёмки этого регрессионного набора.
